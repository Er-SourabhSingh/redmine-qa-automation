## Recurring Issues (addendum, 2026-09-02, same day, later still) — BUG-HLP-028 was itself wrong: misidentified which Redmine menu "the application menu" means

**A real methodology error in this session's own work, caught by the user pointing at a screenshot.** BUG-HLP-028 originally claimed Redmine's application menu is not hidden in the Command Center — that check was against `<ul class="scarlet-topmenu-managed">` (Home/My page/Projects/Helpdesk Command Center/Time Tracker/Workloads/Help/More), which is Redmine's `:top_menu` and is present on literally every page, including the login screen. It was never the menu `HELPDESK_USER_GUIDE.md` §16's "Redmine's application menu is hidden here" claim refers to.

The user showed a real `/projects` screenshot with a **second**, visually distinct nav bar underneath the top one: `Projects / Activity / Issues / Spent time / Gantt / Calendar / News`. Re-verified via `browser_evaluate` enumerating every `<ul>` on the Command Center page: this second bar — Redmine's real `:application_menu`, the same menu that becomes a project's own tab bar (Overview/Activity/Issues/.../Helpdesk/Settings) when inside a project — **has no matching element in the Command Center's DOM at all**, genuinely and completely absent, correctly replaced by the Helpdesk icon rail. So the guide's claim is **true**, and BUG-HLP-028 has been narrowed to its one remaining genuine finding: the header reads "Helpdesk" not "Helpdesk Support". TC-HLP-061/064/072/073's evidence in `HELPDESK_NAVIGATION_WORKSPACES.md` all rewritten to reflect this correctly.

**Generalizable lesson**: Redmine core actually registers at least two separate named menus — `:top_menu` (universal chrome, every page) and `:application_menu` (contextual — global Projects/Activity/Issues/... with no project active, a project's own tabs when one is). A guide or TC claim like "the application menu is hidden/shown" must be checked against the specific menu Redmine itself calls by that name — not assumed to mean whichever nav bar is visually at the top of the page. Two menu bars can coexist on one page; picking the wrong one to test produces a confidently-wrong bug report.

**BUG-HLP-028 closed same day, Rejected/Not a Bug, per explicit user direction with Product Owner context.** Once the application-menu half was corrected (confirmed hidden, see above), the only remaining claim was the header text ("Helpdesk" vs documented "Helpdesk Support"). The user confirmed **the "Helpdesk" header is intentional, per Product Owner request** — not a rendering defect — and that `HELPDESK_USER_GUIDE.md`'s "Helpdesk Support" wording is the outdated side. Corrected the guide (§16) and TC-HLP-061's Expected Result directly to say "Helpdesk"; no bug remains open. This resolves the bug's own "expand the code vs. fix the docs" open question in favor of the docs — settled by the product's actual owner, not inferred from source the way BUG-HLP-013/027 were.
