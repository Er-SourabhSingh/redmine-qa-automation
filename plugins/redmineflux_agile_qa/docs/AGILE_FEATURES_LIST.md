## Notes

- Session 2026-09-18: production Feature **#120436** ("Agile Board: Story Points support", target version *Agile Board Plugin - Release 7.1.0 [21-09-2026]*, client Innoval S.r.l.) arrived In QA. Its four requirements — sprint points in the Backlog, Closed/Total display, completed stories staying visible, and a wider Unassigned column — are added as rows 25-28 above and covered by **TC-AGB-529 to TC-AGB-553** in `testcases/AGILE_BACKLOG_AND_SPRINTS.md`. Sanity subset: TC-AGB-529, 530, 533, 535, 539, 545. Local Redmine 7 build is on branch `feature/backlog-sprint-points` and carries the implementation. Nothing executed yet.
- Session 2026-09-08 (first pass, TC-AGB-001–008): Stage 1 (German, Default theme) first pass on the Agile Board plugin. This plugin is **substantially better localized** than several others tested this cycle (contrast with `BUG-DSH-001`'s near-total absence of coverage) — nearly every UI surface tested (board header, filter bar, Board Settings' Board-Type/Status-columns/Totals/Column-order sections, More Filters panel, Insights panel structure, inline edit modal, quick-add, Backlog Sprints/Versionen tabs) is correctly and thoroughly translated. **3 bugs found**, all Low severity and narrow in scope: `BUG-AGB-001` (6 of 19 card-field checkboxes untranslated), `BUG-AGB-002` (a pluralization-specific gap — plural counts show English "Issues" while singular correctly shows German "Ticket"), `BUG-AGB-003` (an avatar tooltip reads "Unassigned" instead of "Nicht zugewiesen"). Each was proven via DOM/text inspection against clearly-translated sibling strings in the same list/panel, not visual impression alone.
- Session 2026-09-08 (second pass, TC-AGB-009–010): Tested the Global Agile Board and the My Page Agile Board block. Both reuse the same shared board component and both are otherwise well-translated. The Global Board reproduces the identical `BUG-AGB-001`/`BUG-AGB-003` gaps found on the project board (folded in as additional affected surfaces, no new bug IDs). The My Page block surfaced a **broader variant** of `BUG-AGB-001`: its own settings panel shows all 19 "Sichtbare Kartenfelder" checkboxes untranslated, not just the same 6 as elsewhere — also folded into `BUG-AGB-001` rather than filed separately, since the underlying defect (the shared card-field-checkbox component) is the same one.
- Session 2026-09-08 (third pass, TC-AGB-011): Tested the full custom/saved board create→edit→delete lifecycle, explicitly requested as a follow-up. The workflow, its flash messages, and its delete-confirmation modal are all fully and correctly localized — this is the best-covered feature tested on this plugin so far. Found only a narrow third variant of `BUG-AGB-001` (2 of ~19 card fields untranslated on this form specifically), folded into the existing bug rather than filed separately.
- Session 2026-09-08 (fourth pass, TC-AGB-012/013): Tested the Sprint create form and the admin plugin Configure page, explicitly requested as a follow-up ("did you test backlog and agile board plugin configuration"). Found 3 new bugs: `BUG-AGB-004` (3 of 6 Sprint-form field labels untranslated: "Description"/"End date"/"Sharing"), `BUG-AGB-005` (sprint date ranges and version due-dates render in hardcoded English month format instead of the German format core Redmine uses for the identical date, proven via the project's own Roadmap page), `BUG-AGB-006` (the "(Default: ...)" parenthetical is untranslated in all 8 icon-customization rows on the Configure page — otherwise a very thoroughly localized page, including a hidden field's own validation-error text). No UI entry point for sprint edit/delete could be located despite it being documented in the KB — noted as a functional-completeness gap, out of scope for this translation cycle.
- Session 2026-09-08 (fifth pass, TC-AGB-014): Ran Stage 2 (resolution testing, Default theme) at 1280×720 and 1920×1080, explicitly requested as a follow-up. PASS at both — no resolution-specific layout defects across the main board, Board-Einstellungen panel, Weitere Filter panel, and Backlog view.
- Session 2026-09-08 (sixth pass, TC-AGB-015): Ran Stages 3/6 (Lotus theme retest, default + 1280×720), explicitly requested ("now test in theme"). PASS overall — no new Agile-Board-owned bugs from the theme or the theme+resolution combination. `BUG-LTS-001` (the Lotus theme's own sidebar-clipping bug) reconfirmed on a third Forge server via this plugin's project menu. Discovered the project's Story Points feature has since been enabled and its checkbox is untranslated — folded into `BUG-AGB-001` as a 7th affected field (reproduces under Default theme too, unrelated to the theme switch). All resolution/theme testing for this plugin is now complete.
- Session 2026-09-08 (seventh pass, TC-AGB-016): Explicitly asked whether Story Points' field label was tested on the issue detail page and issue edit form, under both themes ("did you tested story point and string on issue detail page and issue form with lotus theme and with standard theme"). Confirmed the same "Story Points" gap reproduces there too, under both Lotus and Default theme identically — folded into `BUG-AGB-001`, whose severity was raised from Low to Medium as a result (the issue detail/edit page is a far more frequently visited surface than the Board Settings panel where this gap was first found).
- Session 2026-09-08 (eighth pass, TC-AGB-017): User spotted from screenshots visual defects on the Sprint/Story Points issue fields under Lotus theme that DOM/translation-focused checks alone hadn't surfaced — a font-style mismatch, a broken bullet-list alignment, and a full-width layout break on the issue edit form. All confirmed via computed styles, absent under Default theme. Filed as `BUG-LTS-003` against the Lotus theme plugin (root cause is the theme's incomplete attributes-grid coverage of plugin-injected fields, not an Agile Board defect) — cross-referenced in this plugin's handoff.
- Session 2026-09-08 (ninth pass, TC-AGB-018): while doing the Lotus theme's own "full core-Redmine sweep," found the project's Settings ("Konfiguration") tab bar has its own "Sprints" sub-tab (`/projects/:id/settings/sprints`) — this is the sprint edit/delete entry point that TC-AGB-012 had reported as unfindable; that note is now corrected. Found a new bug there: the "Freigabe" (Sharing) column shows the raw untranslated enum value "not_shared" for pre-existing fixture sprints while a UI-created sprint correctly shows "Nicht geteilt" — confirmed the underlying value is identical (the Edit form resolves both correctly), so this is a list-view-only display bug, not a data issue. Filed as `BUG-AGB-007` (Low), confirmed theme-agnostic (reproduces under both Lotus and Default).
